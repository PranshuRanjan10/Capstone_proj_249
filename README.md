# CARE-Paddy

Stage-aware, uncertainty-gated irrigation decision support for rice paddies.

> **Work in progress.** Field hydrology is currently generated by a physically-based
> water-balance model driven by weather for the Cauvery delta (Kuruvai and Samba,
> 2015-2024). The ML layer is a forecasting surrogate validated against that simulator,
> **not** against field observations. The ESP32 replaces the simulator without any change
> to the pipeline interface. **No methane has been measured.**

## What it does

Forecasts field water level 1-3 days ahead, checks the forecast against the crop's growth
stage, and recommends MAINTAIN / IRRIGATE / DELAY / DRAIN / INSPECT -- refusing to
automate when its own forecast is too uncertain to trust.

## Quick start

```bash
pip install -r requirements.txt
python run_all.py                    # build data -> train -> evaluate -> explain
python -m pytest tests -q            # decision engine unit tests
streamlit run dashboard/app.py       # dashboard
python iot/sensor_sim.py --fault stuck --interval 1   # virtual ESP32, broken sensor
```

To use real weather instead of the synthetic fallback:

```bash
python src/fetch_power.py --start 2015-01-01 --end 2024-12-31   # run locally
# then set  weather.source: "power"  in config/config.yaml
python run_all.py
```

## Layout

| Path | Purpose |
|---|---|
| `config/config.yaml` | every site and agronomy parameter. Change this, not the code |
| `src/weather.py` | Hargreaves-Samani ET0, POWER loader, forecast degradation |
| `src/staging.py` | GDD -> crop stage, rule-based |
| `src/water_balance.py` | the physical simulator |
| `src/features.py` | lags and rolling windows, leakage rules enforced |
| `src/train.py` | quantile XGBoost vs RF vs persistence, leave-one-season-out |
| `src/decision.py` | pure-function policy + uncertainty gate |
| `src/evaluate.py` | false actuation rate, gating curve, figures |
| `docs/AGENT_SPEC.md` | full specification, pasteable into a coding agent |
| `docs/CORRECTED_REFERENCES.md` | **fix the deck citations before Review-2** |

## Design decisions worth defending

**The ML predicts water level, not "risk".** Risk labels generated from rules and then
predicted from the same features would mean the model just learns the rule back. Water
level is physical, forecastable, and has a real error metric.

**Crop staging is rule-based.** GDD staging is standard agronomy. An ML stage classifier
would add error without adding capability, on data with no stage labels.

**Tree ensembles, not neural networks.** Wu et al. (2023) found XGBoost best on tabular
paddy GHG data ahead of BPNN and 1D-CNN; Ma et al. (2025) ranked Adaboost > XGBoost > RF >
BPNN >> SVM/KNN. We have less data than either.

**Leave-one-season-out, never random.** Daily field state is strongly autocorrelated; a
random split leaks tomorrow into training.

**Train on forecast rainfall, not observed.** At deployment only a forecast exists.
Training on observed and deploying on forecast is a silent leakage bug.

**Drainage is forbidden between panicle initiation and flowering.** Hard agronomic
constraint, evaluated before any model output. There is a unit test asserting it.

## Not claimed

No methane measurement. No field validation. No novelty primacy -- stage-aware irrigation
DSS exists and so does uncertainty-gated automation; we claim integration.
